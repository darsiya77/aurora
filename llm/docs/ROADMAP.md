# План работы

Идём двумя дорожками одновременно.

- **Дорожка А — своя модель с нуля.** Даёт понимание, контроль и собственный актив. Растём по размерам: `tiny` → `small` → `base` → `xl`.
- **Дорожка Б — дообучение готовой открытой модели.** Даёт качество для продукта уже сейчас. Модель на 7–8 млрд параметров, дообученная на наших диалогах, будет умнее нашей `xl`, а стоит в сотни раз дешевле.

Обе дорожки используют одни и те же данные, формат диалогов, оценку и сервер.

## Этап 0. Конвейер работает — готово

- [x] Модель: RMSNorm, RoPE, внимание с группами ключей (GQA), SwiGLU, кэш для генерации
- [x] Токенизатор BPE на байтах, обучается на нашем корпусе
- [x] Чистка, фильтры, удаление персональных данных, дедупликация, бинарные шарды
- [x] Обучение: прогрев и косинусный спад шага, накопление градиентов, bf16, обрезка градиента, сохранение и продолжение, несколько GPU
- [x] Дообучение на диалогах с ошибкой только на ответах ассистента
- [x] Генерация, оценка перплексии, HTTP-сервер в формате, совместимом с OpenAI
- [x] Тесты и прогон `tiny` на процессоре

**Готово, когда**: `scripts/run_tiny.sh` проходит целиком. ✔

- [ ] Аренда одной видеокарты, запуск `configs/small.yaml`

- [ ] Эксперименты: размер словаря, смесь данных, шаг обучения

**Готово, когда**: модель пишет грамотные связные предложения на русском, перплексия на проверке стабильно падает.

## Этап 3. Оценка (параллельно с этапом 2)

- [ ] Свой набор из 200 вопросов: финансы, налоги, риски, мошенничество — с эталонными ответами
- [ ] Открытые русскоязычные тесты на понимание и знания
- [ ] Отчёт сравнения запусков одной командой

**Готово, когда**: любые два чекпоинта сравниваются одной командой и таблицей.

## Этап 4. Ассистент (дорожка Б, 2–3 недели)

- [ ] Выбор открытой модели 7–8 млрд с лицензией, разрешающей коммерческое использование
- [ ] Дообучение адаптерами LoRA на одной видеокарте 24–80 ГБ
- [ ] 3–5 тыс. проверенных диалогов, примеры отказов
- [ ] Обучение на предпочтениях (DPO): учим выбирать честный ответ вместо приятного

**Готово, когда**: на нашем наборе вопросов ассистент отвечает лучше исходной модели и не обещает доходность.

## Этап 5. Безопасность

- [ ] Набор атак: «я сотрудник банка», подмена инструкций в новостях, просьбы обойти правила
- [ ] Модель никогда не исполняет сделки сама: только предлагает, правила проверяет обычный код
- [ ] Регулярный прогон атак перед каждым выпуском модели

## Этап 6. Масштаб (дорожка А, по готовности бюджета)

- [ ] `base` (330 млн) на 8 GPU, затем `xl` (1,2 млрд)
- [ ] Длинный контекст: увеличение окна с масштабированием RoPE

## Этап 7. Работа в продукте

- [ ] Квантование до 8 и 4 бит, сервер с пакетной обработкой запросов
- [ ] Подключение к прототипу Авроры через `/v1/chat/completions`
- [ ] Мониторинг: задержка, стоимость ответа, доля отказов, жалобы

## Как мы работаем

1. Каждое изменение — отдельная ветка и короткое описание: что меняем и как проверили.
2. Перед любым большим запуском — прогон на `tiny`, чтобы не тратить GPU-часы на опечатку.
3. Каждый запуск сохраняет конфиг, логи и чекпоинт в `runs/<имя>/`; результаты записываем в `docs/EXPERIMENTS.md`.
